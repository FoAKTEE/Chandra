# 优化后的任务说明（可直接交给团队或 coding agent）

## 目标

在**不修改模型权重**的前提下（只用闭源 LLM，例如 Claude Code、Codex），仅靠 harness、记忆和搜索，让 LLM 系统在围棋局面中**自己发现**人类先验很低、但客观上很强的着法。

北极星测试：从 AlphaGo 对李世石第二局第 36 手之后的局面出发（黑棋走），系统能否独立找到第 37 手 P10 五路肩冲，或者一手被离线裁判判定同样好的棋。

- 原始需求里写的是"第 47 手"。按公认的"神之一手"理解为第 37 手；系统本身不依赖具体是哪一手。
- 第二个测试：第四局第 78 手 L11，李世石的"神之一手"，也就是 AlphaGo 自己没看到的那一手。

## 核心假设（需要验证，而不是默认成立）

AlphaGo 能下出第 37 手，是因为它在策略网络（System 1）之外还有显式的树搜索（System 2）。LLM 只有被拉长了的 System 1。

我们的假设是：把 LLM 当作策略函数和估值函数，放进一个代码调度的显式搜索里，把搜索结果沉淀成可复用的记忆，就能在不训练的情况下补上 System 2。

这个假设成立的前提是 LLM 的估值和候选点质量"够用"。所以第一步必须先测量这两样东西：
- `gotree prior`：LLM 会不会提出 P10 这类候选；
- `gotree judge-values`：LLM 的胜率估计和 KataGo 的一致程度。

只有这两项过关，才值得投入大预算去搜索。

"自博弈足够多就一定能复现"这句话只在极限意义下成立：UCT 在无限次访问、终局值精确时收敛到 minimax。实际需要的预算随估值误差急剧上升。

## 硬约束

1. **KataGo 只能当对手和离线裁判。**它的任何分析都不能进入搜索、记忆或提示词。裁判结果写在 run 目录之外，worker 的沙箱看不到。
2. 不使用预训练的围棋引擎和网络，也不下载棋谱（包括 AlphaGo 的棋谱）进入记忆。
3. 允许 agent 自己写规则层面的代码，例如提子、征子、Benson 活棋判定、势力草图。允许启发式代码（Heuristic Learning），前提是它从本系统的搜索结果中学出来，并且有回归测试。
4. 防记忆污染：
   - 局面一律按规范朝向呈现，一般和原棋谱的朝向不同；
   - 每次探针都先做 recall 检查，问模型是否认得这盘棋；
   - 主要结论要在一批新生成的、"第 37 手式"的局面上复现，而不是只看这一个名局。

## 系统要求

1. **局面的数据形式。**冻结局面 = 棋子 + 轮到谁 + 劫点 + 是否刚停一手 + 贴目，不包含手顺。
   - 用 8 重对称的规范形式加哈希作为键，这样换位和对称局面会自动合并成同一个节点。
   - 给 LLM 看的是"Position Card"：棋盘四边都标坐标，加上棋块表（气、叫吃、征子）、Benson 活棋判定、势力草图和局部放大窗口。
   - 事实性的东西由代码计算，判断交给 LLM。
2. **记忆采用树或 DAG 形式。**
   - L0：局面 DAG，记录搜索得到的精确结果，跨步、跨盘复用；
   - L1：局部棋形教训，以颜色相对、对称规范化的局部图样为键，相当于系统自己的"定式书"；
   - L2：概念 DAG，每条原则之间用泛化、细化、矛盾三种边相连；
   - L3：代码化的启发式，由 Heuristic Learning 产出并配有回归测试。
3. **长程思考与会话边界。**每个思考任务都开一个全新的会话，不使用 auto-compaction，状态只存在于 DAG 和记忆里。我们方下一手、KataGo 回一手之后，局面就是一个新的冻结残局；搜索树在新根节点处继续复用，不需要恢复任何对话上下文。
4. **搜索。**由代码调度，LLM 只回答窄而明确的问题：
   - 节点上的策略加估值（PUCT + 渐进加宽）；
   - 根节点上的强制广度：最少访问次数、"非常规候选"配额、九个区域各侦察一次、先验噪声；
   - LLM 自博弈 rollout；
   - 专门找反驳的批评任务；
   - 最后的决策。
5. **沉淀与抽象。**只有"意外"才写入记忆，即先验排名和搜索结果明显不一致的情况。教训里不写绝对坐标，只描述棋形。定期整理成概念树，并把高频判断蒸馏成代码。每个任务的记忆检索有字数预算，因此每一步的思考时长可控。

## 评测与成功标准

- **探针分四个阶段**，分别报告：
  - recall：模型是否认得这盘棋；
  - prior：第一次扩展时目标在不在候选里，排第几；
  - 发现曲线：随着预算增加，目标的排名和访问数如何变化；
  - 最终决策。
  
  离线裁判另外给出决策和目标各自损失多少目、在引擎里排第几。
- **最低成功标准：**目标进入根节点前 3 名，并且最终决策的损失不超过 1 目（KataGo 判定）。
- **强成功标准：**决策就是目标；或者在新生成的局面集上，找到"人类先验低、但引擎认可"着法的比例显著高于不带搜索的基线。
- **消融实验**，用来确认功劳归属：不带记忆、不做 rollout、不加根节点广度、只用代码启发式、只用 LLM 不用代码启发式。

## 非目标

- 现阶段不追求在 19 路上整盘战胜强 KataGo。按目前的成本，19 路整盘不可行；先做单点探针，以及 9 路的完整对局。
- 不追求训练或微调任何模型。
